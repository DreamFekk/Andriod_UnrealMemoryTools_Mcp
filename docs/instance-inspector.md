# 2.2 对象实例与结构检查

## 使用

电脑界面进入 SDK 浏览器。在地址栏输入实际 UObject 地址，选 Instance，点击检查；这是对象实例，不是 SDK 中的函数 RVA。结果包含所属 Class、继承链、成员类型、所属类、相对偏移、实际内存地址、值与继承函数。

勾选实时刷新可选 0.5 / 1 / 2 / 5 秒。前一采样与当前采样不同的成员高亮。页面隐藏或设备任务忙时不发起新采样；新请求等待前一个结束。探测代次或对象身份改变时停止。没有暂停游戏，不能视为原子快照。

## 三类地址必须区分

- 对象指针：点击指针值，检查目标 UObject。
- 内嵌结构：点击“展开此结构”，以成员数据地址为起点读取 UScriptStruct 的布局；不先读一个指针。
- 原生结构指针：Struct 模式填写类型定义地址，地址栏填指针槽地址时勾选“先解引用一次”；已经是数据地址时不要勾。未知类型不会由地址自动猜出。

Class 链接与成员名称链接查看元数据定义；“展开此结构”查看实际结构值。返回和标签保留结构类型与解引用状态。数组中的结构体元素也可进入。手动逐级深入不会受单次预览的两层限制，但单次读取仍有时间和数量预算。

## FVector

根据反射结构名称及尺寸识别 Vector、Vector3f、Vector3d 和支持的 Vector_NetQuantize 系列内存布局。12 字节按三个 float32，24 字节按三个 float64；提供 X/Y/Z、scalarType 和可读文字。短读显示 unreadable，不生成看似有效的零向量。NaN / Infinity 保留为明确字符串。普通指针和其他未知结构不会按 float 猜测。

## MCP

umt_explorer 仍是同一个工具，新增 kind=instance/struct、typeAddress、dereference、expectedIdentity。结构模式 typeAddress 必须是当前进程内可验证的 UScriptStruct 元数据对象。结构本身不是 UObject，裸地址不能保证其生命周期；类型和读取地址需来自正确版本。

## 验证方法

以具有 FVector 成员的有效 SceneComponent 实例为例：

1. 检查继承链是否包含 SceneComponent → ActorComponent → Object。
2. 在成员表中打开 RelativeScale3D，核对父级显示的 X/Y/Z 与结构页逐项一致。
3. 12 字节向量应显示偏移 0x0 / 0x4 / 0x8；24 字节向量应显示 0x0 / 0x8 / 0x10。
4. 分别验证对象指针跳转、内嵌结构进入和返回，确认使用的是地址还是指针槽。
5. 切换进程或重新探测后，确认旧 generation / identity 不再继续采样。

类默认对象的值可能不随角色运动变化，测试变化高亮应选实际变化的对象或使用可控 fixture。对象和类型地址只对当前进程生命周期有效，游戏重启后需重新查找。

仓库保留 FVector 值解码和浏览器导航回归；构造数据测试与真实设备触摸测试是不同层次。测试入口见 [贡献指南](../CONTRIBUTING.md)，各游戏构建仍需单独确认布局与读取结果。

## 当前解析范围

内嵌预览两层、每层最多 32 成员、单请求最多 256 嵌套值，达到预算会标记。固定数组为首元素预览；Set/Map 仍为原始头摘要，不是完整稀疏容器遍历。无法反射的私有原生结构需要额外类型信息。当前新增功能是只读观察，不会修改游戏数值。
